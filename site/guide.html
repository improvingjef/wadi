The Oasis Guide

Everything you need to build OCaml projects with oasis.

Your First Project

Create a directory with a library and an executable. You need two things: source files and an oasis.toml manifest.

Project structure

project layout 
myproject/
  oasis.toml
  lib/
    greeting.ml
  app/
    main.ml
lib/greeting.ml 
let hello name =
  Printf.printf "Hello, %s!\n" name
app/main.ml 
let () =
  Greeting.hello "world"

The manifest

oasis.toml 
workspace = "myproject"
version   = 1

[library.greeting]
dir     = "lib"
modules = ["greeting"]

[executable.hello]
dir  = "app"
main = "main"
deps = ["greeting"]

Build and run

$ oasis build
Built library greeting  → _oasis/build/default/lib/greeting/libgreeting.cmxa
Built executable hello  → _oasis/build/default/exe/hello/hello

$ oasis run
Hello, world!

That's it. Oasis resolved the dependency, inferred module compilation order, and built everything. The second time you run oasis build, it will skip both targets because nothing changed.

Adding Dependencies

Libraries can depend on other libraries and on external packages installed via opam.

oasis.toml 
workspace = "server"
version   = 1

[library.core]
dir      = "lib"
modules  = ["config", "router", "handler"]
packages = ["unix"]

[library.db]
dir      = "db"
modules  = ["schema", "query"]
deps     = ["core"]
packages = ["sqlite3"]

[executable.server]
dir  = "bin"
main = "main"
deps = ["db"]

Transitive resolution. The server executable depends on db, which depends on core. Oasis resolves the full closure automatically. External packages propagate too—server gets unix and sqlite3 without declaring them.

Writing Tests

Test targets work like executables but are discovered by oasis test.

oasis.toml (add to the server project) 
[test.unit]
dir  = "test"
main = "test_main"
deps = ["core", "db"]

[test.integration]
dir  = "test"
main = "test_integration"
deps = ["db"]
$ oasis test
ok - unit
ok - integration
2 of 2 tests passed

$ oasis test unit           # run just one
ok - unit
1 of 1 tests passed

Tests exit 0 on success, 1 if any test fails. Each test binary is built before execution.

Manifest Reference

The manifest is a single oasis.toml file at your project root. It uses a subset of TOML with sections, strings, arrays, and integers.

Top-level fields

FieldTypeDescription
workspaceStringProject name (used in install metadata)
versionIntegerManifest version. Must be 1.
membersArrayPaths to member packages (multi-package workspaces)

Libraries

A library is a collection of modules that can be depended on by other targets.

[library.NAME] 
[library.mylib]
dir           = "src"             # required: source directory
modules       = ["core", "util"] # required: module file stems
deps          = ["other_lib"]    # optional: workspace library deps
packages      = ["unix"]         # optional: external ocamlfind packages
actions       = ["codegen"]      # optional: actions to run before build
preprocess    = ["pp"]           # optional: text preprocessors
ppx           = ["ppx_deriving"] # optional: PPX rewriters
compile_flags = ["-w", "-32"]   # optional: compiler flags
link_flags    = ["-lm"]          # optional: linker flags
env           = ["DEBUG=1"]      # optional: environment variables
sandbox       = "target"         # optional: "target" or "workspace"

Module names are file stems without extensions. "core" expects core.ml (and optionally core.mli) in the source directory. Module compilation order is inferred automatically via ocamldep.

Executables

An executable has an entry-point module and optionally additional modules.

[executable.NAME] 
[executable.myapp]
dir     = "bin"           # required: source directory
main    = "main"          # required: entry module stem
modules = ["helpers"]     # optional: additional modules
deps    = ["mylib"]       # optional: library dependencies
packages = ["unix"]       # optional: external packages

The main module is compiled last and linked as the program entry point. It must not appear in the modules list.

Tests

Tests use the same structure as executables. The only difference is that oasis test discovers and runs them.

[test.NAME] 
[test.unit]
dir      = "test"
main     = "test_main"
deps     = ["mylib"]
packages = ["alcotest"]

Actions

Actions are code generation steps that run before compilation. Use them for lexer/parser generators, protobuf compilers, or any tool that produces .ml files.

oasis.toml 
[action.lexer]
argv    = ["ocamllex", "lexer.mll"]
cwd     = "src"
outputs = ["lexer.ml"]

[action.parser]
argv    = ["menhir", "parser.mly"]
cwd     = "src"
outputs = ["parser.ml", "parser.mli"]

[library.lang]
dir     = "src"
modules = ["lexer", "parser", "ast", "eval"]
actions = ["lexer", "parser"]

Actions run in a sandbox. Declared outputs are copied back to the source tree. If an action's inputs haven't changed, the action is skipped on subsequent builds.

FieldRequiredDescription
argvYesCommand and arguments
outputsYesFiles the action produces (relative to cwd)
cwdNoWorking directory (defaults to target dir)
depsNoAdditional input files to track
envNoEnvironment variables (NAME=value)
stdinNoFile to pipe as standard input
sandboxNo"target" or "workspace"

Profiles

Profiles let you define named build configurations with different flags, environment variables, and per-target overrides. Each profile gets its own artifact directory.

oasis.toml 
[profile.release]
compile_flags = ["-O2", "-unbox-closures"]
link_flags    = ["-noassert"]

# Override flags for a specific target in this profile
[profile.release.executable.server]
compile_flags = ["-O3"]
link_flags    = ["-noassert", "-S"]
env           = ["MODE=production"]
$ oasis build --profile release
Built library core     → _oasis/build/release/lib/core/libcore.cmxa
Built executable server → _oasis/build/release/exe/server/server

Profile artifacts are isolated under _oasis/build/<profile>/ so you can have debug and release builds side by side.

Defaults

The [defaults] section sets workspace-wide options that apply to every target unless overridden by a profile or per-target setting.

oasis.toml 
[defaults]
compile_flags = ["-w", "+a-4-40-42"]
sandbox       = "target"

oasis build

signature 
oasis build [--workspace DIR] [--profile NAME] [--backend auto|native|bytecode] [--verbose] [TARGET ...]

Compile libraries, executables, and tests. With no targets, builds everything. Targets are built in dependency order with content-based incremental caching.

  • --workspace DIR — read the manifest from a different directory
  • --profile NAME — select a build profile (default: default)
  • --backend auto|native|bytecode — force a compiler backend
  • --verbose / -v — print compiler invocations as they run

oasis run

signature 
oasis run [--workspace DIR] [--profile NAME] [--backend auto|native|bytecode] [--verbose] [TARGET] [-- ARG ...]

Build and launch an executable. If the workspace has a single executable, the target is optional. Arguments after -- are forwarded directly. Process spawning is direct—signals, streaming IO, and exit codes are preserved exactly.

$ oasis run server -- --port 8080 --verbose
Listening on :8080

oasis test

signature 
oasis test [--workspace DIR] [--profile NAME] [--backend auto|native|bytecode] [--verbose] [TARGET ...]

Build and run test targets. With no targets, runs all tests. Reports TAP-style output with a pass/fail summary. Exits 0 if all tests pass, 1 if any fail.

oasis clean

signature 
oasis clean [--workspace DIR] [--profile NAME] [--verbose] [TARGET ...]

Remove build artifacts. With no targets, removes the entire _oasis/ tree. With targets, removes only those outputs and prunes empty directories.

oasis explain

signature 
oasis explain [--workspace DIR] [--profile NAME] [--backend auto|native|bytecode] [--current] [--json] [TARGET ...]

Show why a target was rebuilt or reused. Displays fingerprint diffs, compiler invocations, include paths, and module order.

  • --current — dry-run: compute what would happen without compiling
  • --json — machine-readable JSON output
$ oasis explain core
target core: rebuilt
  reason: source changed lib/engine.ml
  fingerprint: manifest a3f8c1 sources 9e2b07 toolchain d41d8c

oasis install

signature 
oasis install [--workspace DIR] [--profile NAME] [--backend auto|native|bytecode] [--prefix DIR] [--destdir DIR] [--verbose] [TARGET ...]

Stage libraries, executables, and metadata for distribution. Generates findlib-compatible META files. Resolves transitive library closures automatically.

  • --prefix DIR — install root (default: _oasis/install/<profile>)
  • --destdir DIR — prepend to prefix for package-manager staging

oasis toolchain

signature 
oasis toolchain

Print the resolved OCaml compiler paths, backend selection, stdlib location, and package search roots. The first thing to run when something doesn't build.

oasis graph

signature 
oasis graph [--workspace DIR] [--profile NAME] [--backend auto|native|bytecode] [TARGET ...]

Show target build order, module compilation order, and active action/preprocess/PPX pipelines without compiling anything.

oasis deps

signature 
oasis deps [--workspace DIR] [TARGET ...]

Resolve and display transitive external package requirements for selected targets.

oasis env

signature 
oasis env [--workspace DIR] [--profile NAME] [--json] SUBTOOL [TARGET ...]

Print the exact subprocess environment a build, run, test, or install step would inherit. Useful for debugging environment-sensitive builds.

oasis repl

signature 
oasis repl [--workspace DIR] [--profile NAME] [--verbose] [TARGET] [-- OCAML_ARG ...]

Build a bytecode toplevel with workspace libraries and packages already loaded. Great for interactive exploration of your library API.

oasis migrate

signature 
oasis migrate [--workspace DIR] [--output PATH] [--stdout] [--force]

Scan dune and dune-project files and generate a first-pass oasis.toml with review comments for anything that needs manual attention.

oasis completion

signature 
oasis completion [--workspace DIR] bash|zsh|fish

Generate shell completion scripts. Completions use a runtime query protocol so they stay accurate as your project changes.

$ oasis completion bash >> ~/.bashrc
$ oasis completion zsh > ~/.zfunc/_oasis

oasis docs

signature 
oasis docs

Render markdown CLI reference from the live command table. Single source of truth for help text, docs, and completions.

Incremental Builds

Oasis uses content-based fingerprints, not timestamps. A target is rebuilt only when its inputs actually change. The fingerprint includes:

  • Compiler version and backend
  • Manifest hash
  • Source file digests (every .ml and .mli)
  • Toolchain paths (ocamlc, ocamlopt, ocamldep, ocamlfind)
  • Resolved package locations
  • Dependency library fingerprints

Fingerprints are stored in .oasis-stamp files alongside build artifacts. Use oasis explain to see exactly what changed.

Toolchain Resolution

Oasis resolves compilers and tools in a predictable order:

  1. Environment variables: OCAMLC, OCAMLOPT, OCAMLDEP, OCAMLFIND
  2. PATH lookup

Backend selection follows: if --backend is specified, use it. Otherwise try native (ocamlopt), fall back to bytecode (ocamlc). External packages are resolved via ocamlfind query.

Run oasis toolchain to see exactly what was resolved:

$ oasis toolchain
ocamlopt:         /home/dev/.opam/default/bin/ocamlopt
ocamldep:         /home/dev/.opam/default/bin/ocamldep
ocamlfind:        /home/dev/.opam/default/bin/ocamlfind
selected-backend: native
compiler-version: The OCaml compiler, version 5.1.0
stdlib:           /home/dev/.opam/default/lib/ocaml

Multi-Package Workspaces

Large projects can split into member packages. The root manifest declares members; each member has its own targets while inheriting workspace defaults and profiles.

oasis.toml (root) 
workspace = "myproject"
version   = 1
members   = ["packages/core", "packages/cli"]

[defaults]
compile_flags = ["-w", "+a-4-40-42"]

[profile.release]
compile_flags = ["-O2"]
packages/core/oasis.toml 
[library.core]
dir     = "src"
modules = ["engine", "types"]

Member manifests cannot define their own defaults or profiles—those are inherited from the root. Actions, preprocessors, and PPX tools defined in member manifests are automatically scoped to the member's directory.
